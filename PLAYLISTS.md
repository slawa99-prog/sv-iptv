# SV ТВ — заменяемые плейлисты для Televizo

[Открыть управление](https://github.com/slawa99-prog/sv-iptv/actions/workflows/playlists.yml) · [Постоянные ссылки и состояние](managed/README.md)

На приставке один раз добавляются четыре постоянные ссылки. Затем владелец меняет источник нужного списка через форму; зритель получает новый состав при очередном обновлении Televizo. Это ручной выбор замены владельцем с автоматической доставкой пользователям и регулярным обновлением выбранного источника.

## Добавить на приставку

В Televizo создайте новый M3U-плейлист **по ссылке**, а не из скачанного файла:

| Название в Televizo | Постоянная ссылка | Начальный источник |
|---|---|---|
| SV ТВ 1 | https://raw.githubusercontent.com/slawa99-prog/sv-iptv/main/managed/tv1.m3u | Основной SV IPTV по последнему отчёту ПК |
| SV ТВ 2 | https://raw.githubusercontent.com/slawa99-prog/sv-iptv/main/managed/tv2.m3u | Российский список iptv-org |
| SV ТВ 3 | https://raw.githubusercontent.com/slawa99-prog/sv-iptv/main/managed/tv3.m3u | Российский список ngrch |
| SV ТВ 4 | https://raw.githubusercontent.com/slawa99-prog/sv-iptv/main/managed/tv4.m3u | Российский список dearbulut |

Сначала проверьте [состояние публикации](managed/README.md): при ошибке первой загрузки соответствующий файл ещё не существует. Дополнительные источники уже использовались в каталоге SV IPTV, но здесь публикуются их целые подборки. Состав, повторы и качество у них могут различаться. Разные авторы могут использовать одни и те же серверы вещания.

В настройках **каждого** плейлиста включите регулярное обновление. Выберите доступную в вашей версии Televizo частоту; не оставляйте «Никогда». Первый раз обновите вручную и проверьте несколько каналов. Изменение на сервере не перезапускает автоматически уже зависший канал: может понадобиться открыть его заново.

Существующий основной адрес `.../main/tv.m3u` продолжает работать по прежней схеме. Управление заменой действует только на новые адреса `.../main/managed/tv1.m3u` — `tv4.m3u`. Чтобы существующие покупатели получали такие замены, им нужно один раз добавить эти новые ссылки. Удалённо заменить ранее загруженный локальный файл на приставке этот сервис не может.

## Заменить целый список

1. Войдите в GitHub под `slawa99-prog` и откройте [управление](https://github.com/slawa99-prog/sv-iptv/actions/workflows/playlists.yml).
2. Нажмите **Run workflow**. Оставьте ветку **main**.
3. В поле «Что сделать» выберите **Заменить источник**.
4. Выберите **tv1**, **tv2**, **tv3** или **tv4**.
5. Вставьте прямую общедоступную ссылку на M3U автора. Либо оставьте ссылку пустой и выберите готовый источник.
6. Нажмите зелёную **Run workflow** и дождитесь зелёного результата запуска.

Ссылка, вставленная вручную, имеет приоритет над готовым источником. Ссылка страницы GitHub вида `/blob/…` не подходит: нужна ссылка на сырой M3U. В форме не нужно вводить токены GitHub. Репозиторий публичный: исходные URL и содержимое плейлистов будут доступны всем; личные ключи, пароли и индивидуальные платные ссылки сюда не добавляйте.

Если запуск красный, откройте шаг «Получить и подготовить плейлисты» и [состояние](managed/status.json). Некорректная ручная замена сохраняет прежний источник и файл. При обычном обновлении ошибка одного автора не мешает обновить остальных.

Для возврата используйте **Вернуть предыдущую версию**. Сервис восстановит последний сохранённый состав и источник, затем поставит автоматическое обновление этой позиции на паузу. Так проблемный свежий список не вернётся через час. После проверки используйте **Возобновить автообновление** или снова **Заменить источник**. Доступна одна предыдущая версия; более ранние версии остаются в истории GitHub.

## Что выполняется автоматически

- Раз в час, примерно в 37-ю минуту, загружаются свежие версии текущих источников. GitHub может задерживать расписание.
- При изменении проверенного основного `tv.m3u` запускается обновление управляемых позиций.
- Сохраняются названия каналов, ID, категории, телепрограмма, логотипы и специальные параметры плеера. Относительные адреса превращаются в абсолютные относительно реального адреса источника после перенаправлений.
- HTML, пустой файл, повреждённый M3U и HLS одного канала не заменяют опубликованный плейлист.
- Если при регулярном обновлении число записей падает более чем вдвое, сохраняется предыдущая версия. Для осознанного перехода на меньший список используется явная операция замены.
- Старый файл сохраняется и при сетевой ошибке. В статусе будет указано, что это прежняя версия, а не свежая успешная загрузка.

Проверяется **доступность и структура файла плейлиста**. Здесь нет автоматического поиска новых авторов, проверки эфира каждого канала или бесшовного переключения во время просмотра. Полные проверки потоков существующего SV IPTV продолжаются отдельно. Обычные IPTV-списки поддерживаются; специальные форматы, требующие нестандартной обработки плеером, могут потребовать адаптации.

Приставки скачивают только список ссылок; видео идёт от авторских источников непосредственно на устройства. Постоянно включённый домашний ПК для этой системы не нужен. Работоспособность зависит от GitHub, авторов источников и доступа к ним из сети покупателя. После длительного отсутствия активности GitHub может отключить расписание — проверяйте дату последнего запуска.

## Техническая проверка

```bash
python -m unittest discover -s playlist_manager/tests -v
python playlist_manager/manager.py --action refresh
python playlist_manager/manager.py --action replace --slot tv2 --source 'https://author.example/playlist.m3u'
python playlist_manager/manager.py --action rollback --slot tv2
```

Ручные параметры передаются в задачу через переменные окружения и не подставляются в shell-код. Запись ограничена папкой `managed/`; основной `tv.m3u`, история проверок и каталог каналов не меняются. Замена конфигурации и файлов публикуется одним коммитом. Конкурирующее изменение в репозитории не перезаписывается принудительно.
