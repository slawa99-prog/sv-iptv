# SV IPTV 3.0

Российские телеканалы для Televizo. Цель — **не менее 100 разных каналов** с проверкой реального эфира и заменой неработающих ссылок. Наличие канала в каталоге ещё не означает, что его поток прошёл проверку.

**Текущая сборка: 277 уникальных каналов**, проверка 30.10.2026 19:06–19:41 по Оренбургу (UTC+5). Требование минимум 100 выполнено. Из них 275 прошли и утренний, и вечерний контроль. Подробности и ограничения — в `CHECK-RESULTS.md`.

## Что изменено

- Расширенный каталог вместо ограничения на 32 канала.
- HD/SD объединены. Временные сдвиги `+2`, `+4` не используются как замена основного эфира. В итоговом M3U проверяются совпадения ID, названий, исходных URL и выбранных медиапотоков.
- Запасные ссылки находятся в `backups.json`, поэтому не дублируют каналы в Televizo.
- Проверяются полные видеофрагменты, звук, декодирование кадров, скорость загрузки и появление нового фрагмента эфира. HTTP 200 недостаточно.
- Для проверки выбирается вариант до 720p и 4 Мбит/с, если он есть. В M3U сохраняется исходный входной URL, чтобы плеер получал свежие адреса CDN и выбирал качество. Это не принудительное ограничение качества Televizo.
- История сохраняется и при ошибках. Повторные запуски подряд не создают искусственные дни «стабильности».
- Если прошло менее 100 каналов или число резко упало, новый основной плейлист не публикуется. Старый файл сохраняется, но его прежнее количество не считается текущим числом рабочих каналов.

## Значение стабильности

Первое успешное испытание даёт статус `probation`: поток воспроизводился во время проверки. `observed_stable` требует минимум **8 разнесённых проверок за 42 часа** и **90% успехов**. Учитываются до 56 наблюдений за 14 дней. Проверки с интервалом менее двух часов не добавляют независимых наблюдений; успешный повтор не стирает сбой в том же интервале.

Это оценка коротких наблюдений, а не мониторинг 24/7. Проверка не распознаёт визуальную заглушку, неправильную передачу или неподвижную картинку с живыми временными метками. Доступность в домашней сети может отличаться от сети проверки и GitHub.

При отказе выбранного потока исправный резерв подставляется в следующей сборке. **Televizo должен обновить плейлист и заново открыть канал.** Автоматического переключения посреди просмотра этот M3U не обеспечивает.

## Постоянная ссылка

Репозиторий: [slawa99-prog/sv-iptv](https://github.com/slawa99-prog/sv-iptv).

Добавьте в Televizo M3U-плейлист **по ссылке**, название `SV IPTV`:

```text
https://raw.githubusercontent.com/slawa99-prog/sv-iptv/main/tv.m3u
```

По ссылке опубликовано **277 уникальных каналов**, прошедших проверку 30.10.2026 в 19:06–19:41 по Оренбургу. Эта сборка заменила начальный список из 91 канала. M3U и отчёты обновлены вручную из успешного запуска GitHub Actions; даты дальнейших проверок смотрите в `status.json` и Actions.

**С 30.10.2026 включены проверки GitHub Actions с доступом только на чтение. Автоматическое изменение M3U пока выключено.** Результаты новых проверок находятся в [Actions](https://github.com/slawa99-prog/sv-iptv/actions): выберите запуск, посмотрите сводку и архив `sv-iptv-check-results`. Архив хранится 7 дней. Значение `published` в отчёте архива означает создание сборки внутри запуска, а не изменение постоянной ссылки.

Проверки запланированы каждые шесть часов: примерно **06:17, 12:17, 18:17 и 00:17 по Оренбургу**. Запуск может задерживаться. Для ручного запуска откройте **Actions → SV IPTV — проверка каналов → Run workflow**.

Автоматическая публикация подготовлена, но требует отдельного разрешения `contents: write` для workflow этого репозитория. До его включения новые результаты и история сохраняются в архив запуска; следующие запуски начинают с истории в репозитории. Основной список по ссылке остаётся последней вручную опубликованной сборкой, пока запись не разрешена.

После включения записи новая сборка должна пройти минимум 100 каналов и проверку резкого падения количества. При неудачной проверке основной M3U сохраняется; его прежнее количество не означает, что все каналы прошли последнюю проверку. В Televizo нужно включить регулярное обновление плейлиста, если оно доступно в установленной версии.

Проверяйте дату последнего запуска: GitHub может отключать расписания публичных репозиториев после длительного отсутствия активности. Личные токены в проект не включены.

## Запуск на компьютере

Нужны Python 3.10+ и `ffmpeg`/`ffprobe` в PATH. Дополнительных Python-пакетов нет.

```bash
python -m unittest discover -s tests -v
python sv_iptv.py
```

На Windows после установки зависимостей можно запустить `CHECK-WINDOWS.cmd`. Проверка идёт из вашей сети и может занять десятки минут. Компьютер должен оставаться включённым.

Если проверка прервалась, её можно продолжить командой `python sv_iptv.py --resume`. Скрипт использует только результаты того же проверяющего алгоритма моложе одного часа; более старые проверяет заново. Промежуточные результаты сохраняются автоматически каждые пять потоков.

Готовый `tv.m3u` можно сразу импортировать в Televizo как локальный файл. Такой файл сам не обновляется: для обновления нужно импортировать свежую сборку или после публикации проекта перейти на постоянную ссылку.

Только список кандидатов, без проверки эфира:

```bash
python sv_iptv.py --inventory
```

## Источники и ограничения

- [iptv-org/iptv](https://github.com/iptv-org/iptv): российская подборка и `streams/ru.m3u`. Две формы одного каталога, не независимые вещатели.
- [smolnp/IPTVru](https://github.com/smolnp/IPTVru): дополнительные URL из `IPTVstable.m3u8`. Название источника не заменяет проверку.
- [Free-TV/IPTV](https://github.com/Free-TV/IPTV/blob/master/lists/russia.md): дополнительные российские потоки.
- [ngrch/iptv](https://github.com/ngrch/iptv): дополнительные адреса; ID источника сопоставлены с ID проекта явно, временные сдвиги не объединяются с основным эфиром.
- [dearbulut/iptv](https://dearbulut.github.io/iptv/playlists/country/ru.m3u): ещё один источник адресов; его предварительный статус доступности не заменяет проверку видео и звука в SV IPTV.
- [iptv-org API](https://github.com/iptv-org/api): ID, названия, категории и дополнительные адреса потоков из `streams.json`.

Каталоги загружаются заново при сборке. Новые URL включённых каналов подхватываются автоматически; новый канал требует записи в `channels.json`. Видеосигнал не ретранслируется, короткие фрагменты для проверки удаляются.

В `custom.m3u` сохранены сопоставленные адреса из снимка IPTVru от 27.10.2026: во время сборки 28.10 исходный файл возвращал 404. Это позволяет продолжать проверку адресов после исчезновения каталога. Такие записи не считаются рабочими автоматически: они проходят те же проверки эфира. Для региональных каналов без ID iptv-org используются ID с префиксом `sv.`; город сохранён в названии, когда это нужно для различения одноимённых каналов.

По умолчанию одновременно проверяются четыре потока, не более двух с одного сервера. Это уменьшает влияние нагрузки самой проверки на измерение скорости загрузки.

Проверяется незашифрованный HLS с совмещёнными или отдельными аудио и видео. При отдельных дорожках проверяются загрузка и декодирование обеих, а также обновление обоих плейлистов. Для короткого окна HLS длительность проверки накапливается по нескольким новым фрагментам; минимальные 12 секунд сохраняются.

DASH, DRM и byte-range HLS пропускаются. Поэтому отказ этого проверяющего скрипта не всегда означает, что поток невозможно открыть другим плеером. Телепрограмма по умолчанию не включена: соответствие ID и XMLTV ещё не проверено.

Справка: [GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows), [FFmpeg](https://ffmpeg.org/ffmpeg.html).
