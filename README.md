# SV IPTV 3.1

**Заменяемые подборки для Televizo:** [управление и инструкция](PLAYLISTS.md) · [постоянные ссылки SV ТВ 1–4](managed/README.md). Источник целого плейлиста можно поменять централизованно; его адрес на приставках остаётся прежним. Основной `tv.m3u` сохраняет существующий порядок публикации по проверке ПК.

Российские и русскоязычные телеканалы для Televizo. Цель — **не менее 100 разных каналов** с проверкой реального эфира и заменой неработающих ссылок. Наличие канала в каталоге ещё не означает, что его поток прошёл проверку.

**Основной плейлист: 452 канала в 20 категориях.** 11.11.2026 по просьбе владельца из сборки 585 каналов исключены 133 иноязычные и неподтверждённые многоязычные версии. Сохранены российские каналы, включая региональные, и русскоязычные версии зарубежных каналов. Это изменение состава: последняя проверка ПК по-прежнему завершена в 13:52 по Оренбургу, адреса и настройки оставшихся потоков не изменены. Строгая стабильность по новым визуальным критериям пока не подтверждена ни у одной выбранной ссылки.

Постоянный [`tv.m3u`](tv.m3u) теперь обновляется по проверенным отчётам ПК. Автоматические проверки GitHub продолжаются, но их сборка сохраняется отдельно в [`cloud.m3u`](cloud.m3u): зарубежная проверка не заменяет домашнюю и не удаляет доступные только из России адреса. Дата и состав основного списка — в [`home-review.json`](home-review.json); статистика GitHub — в [`status.json`](status.json).

Категории всех 1431 известных кандидатов закреплены по ID в [`channel-groups.json`](channel-groups.json). «Региональные» содержит местные вещатели; многотематические каналы выделены в «Общие», животные — в «Природа и животные», путешествия — в «Путешествия». Источник больше не может вернуть Travel Channel или «В мире животных» в региональные. Новые каналы без понятной тематики получают «Общие» до уточнения. Полный состав опубликованного списка — в [`CHANNELS.md`](CHANNELS.md).

## Состав основного плейлиста

Правило `channel_scope` в `config.json` допускает 674 ID после языкового отбора и сверки истории проверки из общего исследовательского каталога 1431 позиции. Оно применяется после обновления источников и перед экспортом. Исключённые и новые непроверенные ID не возвращаются автоматически; качество воспроизведения по-прежнему проверяется отдельно. Русский язык каждой звуковой дорожки этим правилом не распознаётся.

[Список исключений и основания](language-selection-2026-11-11.json). Предыдущие 585 записей и сведения о проверке сохранены в `previous/`. Общий каталог, адреса и история не удалены. Отдельный зарубежный плейлист пока не создавался.

## Исключения по истории проверки 13.11.2026

По 12 домашним циклам и 29 опубликованным отчётам российского VPS исключены **182 канала**, проверявшиеся в обеих сетях без единого записанного успеха. [Полный список и основания](check-pruning-2026-11-13.json). Любой прежний успех сохраняет канал; 277 позиций без полной проверки в обеих сетях также оставлены.

Полная очередь ПК сокращена с 1432 до **1250 каналов**, с 21 897 до **20 802 запросов**. Все варианты оставленных каналов сохранены. Из первоначальных 341 исследовательской ссылки оставлены 340: RTVi US исключён по этому же правилу. История измерений сохранена и не переносится между сетями. Правило действует при обновлении источников и старой очереди. Российский сервер получает обновлённый `config.json` перед следующим циклом; для ПК требуется обновлённый комплект 3.8.

В действующем `tv.m3u` таких каналов нет: все **452** имели успешные проверки. Этот разбор не является новой проверкой их доступности.

## Проверка заглушек с 11.11.2026

Основная автоматическая проверка GitHub теперь применяет одинаковый визуальный
фильтр ко всем проверяемым адресам: старым каналам, резервам и новым кандидатам,
добавленным обнаружением каталога. В наборе 19 известных образцов, включая
CINERAMA на русском и узбекском языках и экран «Поток недоступен».
После декодирования видео и звука из каждого проверяемого окна извлекаются
два кадра; проверяются и последующие свежие фрагменты. Совпадение с заглушкой
или невозможность проверить кадр исключает поток из успешных результатов.
Нулевые размеры видеодорожки также не принимаются за воспроизводимое видео.

Кадры и результаты сравнения сохраняются в `review-frames/` внутри артефакта
Actions `sv-iptv-check-results` на 7 дней; в историю git изображения не записываются.
В `status.json` добавлены `known_placeholder_streams`, `visually_checked_streams`
и отпечаток `visual_criteria`. Старый кэш проверки недействителен после смены
алгоритма или образцов. Старая техническая история сохраняется, но для строгой
стабильности нужно накопить минимум 8 наблюдений с текущей визуальной проверкой
за 42 часа при прежнем пороге 90% успехов. Один успех после заглушки не стирает
сбой в том же двухчасовом интервале.

Если защита количества сохраняет прежнюю облачную сборку, точные адреса с
подтверждёнными заглушками удаляются и из неё; сетевой таймаут сам по себе
такое удаление не запускает. Основной `tv.m3u` по-прежнему обновляется по отчётам
ПК, отдельно от облачной проверки. `new-channels.m3u` и `expanded-preview.m3u`
остаются датированными подборками от 10.11, а не автоматически обновляемыми
результатами каждого запуска.

Фильтр распознаёт известные изображения в выборке кадров. Он не подтверждает
название канала, не гарантирует отсутствие неизвестных заставок и рекламы между
проверками и не заменяет проверку из России. Отдельный менеджер внешних подборок
`managed/tv1–4.m3u` обновляет списки целиком и не выполняет этот тест каждого эфира.

## Расширение каталога 11.11.2026

Каталог для проверки расширен с 1125 до **1431 позиции**: **306 новых кандидатов**. В полном комплекте для ПК сохранены **21 883 разных запроса** (URL и настройки), включая все **4384** адреса последнего отчёта и всю присланную историю. Это кандидаты, а не 1431 работающий канал. [Подробности расширения](EXPANSION-2026-11-11.md).

Для новых относительно репозитория ID добавлен ограниченный входной набор `expansion-candidates.m3u`; автоматическая сборка проверяет его тем же декодером и визуальным фильтром. Полный перебор всех вариантов выполняется комплектом ПК.

## Что изменено

- Базовый каталог дополняется автоматически из русскоязычной подборки iptv-org. Новый канал должен иметь известный ID и пройти проверку эфира; закрытые каналы, неоднозначные имена и временные сдвиги не добавляются. Число найденных дополнений указано в `status.json` → `catalog_discovery`.
- HD/SD объединены. Временные сдвиги `+2`, `+4` не используются как замена основного эфира. В итоговом M3U проверяются совпадения ID, названий, исходных URL и выбранных медиапотоков.
- Запасные ссылки находятся в `backups.json`, поэтому не дублируют каналы в Televizo.
- Проверяются полные видеофрагменты, звук, декодирование кадров, скорость загрузки и появление нового фрагмента эфира. HTTP 200 недостаточно.
- Для проверки выбирается вариант до 720p и 4 Мбит/с, если он есть. В M3U сохраняется исходный входной URL, чтобы плеер получал свежие адреса CDN и выбирал качество. Это не принудительное ограничение качества Televizo.
- История сохраняется и при ошибках. Повторные запуски подряд не создают искусственные дни «стабильности».
- Если проверку GitHub прошло менее 100 каналов или число резко упало, новая облачная сборка не публикуется. Старый файл сохраняется, но его прежнее количество не считается текущим числом рабочих каналов.

## Значение стабильности

Первое успешное испытание даёт статус `probation`: поток воспроизводился во время проверки. `observed_stable` требует минимум **8 разнесённых проверок за 42 часа** и **90% успехов**. Учитываются до 56 наблюдений за 14 дней. Проверки с интервалом менее двух часов не добавляют независимых наблюдений; успешный повтор не стирает сбой в том же интервале.

Это оценка коротких наблюдений, а не мониторинг 24/7. Проверка распознаёт известные заглушки по образцам; неизвестную заставку, неправильную передачу или неподвижную картинку с живыми временными метками она может пропустить. Доступность в домашней сети может отличаться от сети проверки и GitHub.

В автоматической облачной сборке при отказе выбранного потока исправный резерв подставляется после следующей проверки GitHub. Основной `tv.m3u` получает замены после нового отчёта ПК и проверки состава. **Televizo должен обновить плейлист и заново открыть канал.** Автоматического переключения посреди просмотра этот M3U не обеспечивает.

## Постоянная ссылка

Репозиторий: [slawa99-prog/sv-iptv](https://github.com/slawa99-prog/sv-iptv).

Добавьте в Televizo M3U-плейлист **по ссылке**, название `SV IPTV`:

```text
https://raw.githubusercontent.com/slawa99-prog/sv-iptv/main/tv.m3u
```

Постоянная ссылка сохраняется при каждой новой сборке. Для неё количество каналов и дата проверки находятся в `home-review.json`. С 10.11.2026 настройка `publication_mode: reviewed-local` защищает этот файл от автоматической замены результатами другой сети. Чтобы обновить основной состав, нужен новый отчёт ПК с проверкой кадров; запись нового M3U и `home-review.json` выполняется вместе.

**С 31.10.2026 включена автоматическая запись результатов GitHub Actions.** Запуски находятся в [Actions](https://github.com/slawa99-prog/sv-iptv/actions). Архив `sv-iptv-check-results` хранится 7 дней. Успешный шаг «Сохранение истории и плейлиста» подтверждает запись в репозиторий; статус `published` означает, что новая сборка прошла условия публикации.

Проверки запланированы каждые шесть часов: примерно **06:17, 12:17, 18:17 и 00:17 по Оренбургу**. Запуск может задерживаться. Для ручного запуска откройте **Actions → SV IPTV — проверка каналов → Run workflow**.

Облачная история сохраняется после каждого завершённого контроля, включая неудачные проверки. Следующий запуск использует накопленные наблюдения. При недоступности выбранного адреса исправный резерв может стать основным в следующем `cloud.m3u`.

Новая облачная сборка должна содержать минимум 100 прошедших каналов и пройти проверку резкого падения количества. При неудачной проверке предыдущий `cloud.m3u` сохраняется; его прежнее количество не означает, что все каналы прошли последнюю проверку. В Televizo нужно включить регулярное обновление основного плейлиста, если оно доступно в установленной версии.

Проверяйте дату последнего запуска: GitHub может отключать расписания публичных репозиториев после длительного отсутствия активности. Личные токены в проект не включены.

## Запуск на компьютере

Нужны Python 3.10+ и `ffmpeg`/`ffprobe` в PATH. Дополнительных Python-пакетов нет.

```bash
python -m unittest discover -s tests -v
python sv_iptv.py --local
```

На Windows после установки зависимостей можно запустить `CHECK-LOCAL.cmd`. Проверка идёт из вашей сети и может занять десятки минут. Компьютер должен оставаться включённым. Результаты сохраняются отдельно в `local-check/`. Ваш отдельный полный проверяющий комплект со `START.cmd` продолжает работать как раньше; его накопленная история этим обновлением репозитория не изменяется.

Если проверка прервалась, её можно продолжить командой `python sv_iptv.py --local --resume`. Скрипт использует только результаты того же проверяющего алгоритма моложе одного часа; более старые проверяет заново. Промежуточные результаты сохраняются автоматически каждые пять потоков.

Результат `local-check/tv.m3u` — автоматический технический отбор. Перед заменой основного списка нужно проверить кадры на заглушки и подмены. Локальный файл сам не обновляется; постоянная ссылка получает изменения после публикации нового проверенного отчёта.

Только список кандидатов, без проверки эфира:

```bash
python sv_iptv.py --inventory
```

## Источники и ограничения

- [iptv-org/iptv](https://github.com/iptv-org/iptv): российская подборка и `streams/ru.m3u`. Две формы одного каталога, не независимые вещатели.
- [Русскоязычная подборка iptv-org](https://iptv-org.github.io/iptv/languages/rus.m3u): новые идентифицированные каналы и их адреса. Язык вещания может быть одним из нескольких языков канала.
- [denxvofficial/IPTV](https://github.com/denxvofficial/IPTV): дополнительные адреса, сопоставляемые с каталогом по названию. Само наличие адреса в источнике не означает прохождения проверки.
- [Free-TV/IPTV](https://github.com/Free-TV/IPTV/blob/master/lists/russia.md): дополнительные российские потоки.
- [ngrch/iptv](https://github.com/ngrch/iptv): дополнительные адреса; ID источника сопоставлены с ID проекта явно, временные сдвиги не объединяются с основным эфиром.
- [dearbulut/iptv](https://dearbulut.github.io/iptv/playlists/country/ru.m3u): ещё один источник адресов; его предварительный статус доступности не заменяет проверку видео и звука в SV IPTV.
- [iptv-org API](https://github.com/iptv-org/api): ID, названия, категории и дополнительные адреса потоков из `streams.json`.

Каталоги загружаются заново при сборке. Новые URL включённых каналов и новые каналы из русскоязычной подборки iptv-org подхватываются автоматически. `channels.json` остаётся базовым каталогом с ручными уточнениями. Дополнения сверяются с метаданными iptv-org; закрытые и переименованные каналы, 18+, известные дубли международных версий и конфликты имён пропускаются. При недоступности источника используется снимок `seed/catalog-discovery.json` возрастом до 72 часов. Добавление в каталог не даёт каналу статуса рабочего или стабильного: проверка эфира и история обязательны. Видеосигнал не ретранслируется, короткие фрагменты для проверки удаляются.

В `custom.m3u` сохранены сопоставленные адреса из снимка IPTVru от 27.10.2026: во время сборки 28.10 исходный файл возвращал 404. Это позволяет продолжать проверку адресов после исчезновения каталога. Такие записи не считаются рабочими автоматически: они проходят те же проверки эфира. Для региональных каналов без ID iptv-org используются ID с префиксом `sv.`; город сохранён в названии, когда это нужно для различения одноимённых каналов.

По умолчанию одновременно проверяются шесть потоков, не более двух с одного сервера. Это уменьшает влияние нагрузки самой проверки на измерение скорости загрузки.

Проверяется незашифрованный HLS с совмещёнными или отдельными аудио и видео. При отдельных дорожках проверяются загрузка и декодирование обеих, а также обновление обоих плейлистов. Для короткого окна HLS длительность проверки накапливается по нескольким новым фрагментам; минимальные 12 секунд сохраняются.

DASH, DRM и byte-range HLS пропускаются. Поэтому отказ этого проверяющего скрипта не всегда означает, что поток невозможно открыть другим плеером. Телепрограмма по умолчанию не включена: соответствие ID и XMLTV ещё не проверено.

Справка: [GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows), [FFmpeg](https://ffmpeg.org/ffmpeg.html).

Предварительная сверка каталога на 08.11 дала 134 дополнения к 479 базовым названиям. Это число кандидатов, а не число рабочих каналов. Актуальные итоги: `catalog_channels`, `catalog_discovery.added`, `unique_channels_passed` и `last_published_count` в `status.json`.

Проверки сейчас выполняются в сети GitHub. Российский сервер или домашний компьютер к автоматике ещё не подключён; доступность в России нельзя заключать только по результату GitHub. Для отдельной проверки в своей сети можно скачать проект и запустить `CHECK-LOCAL.cmd` после установки Python и FFmpeg, либо выполнить `python sv_iptv.py --local`. Результаты и собственная история сохраняются в папке `local-check/`; история GitHub не копируется и не изменяется. Этот режим также проверяет помеченные географическими ограничениями адреса. Он сам не меняет местоположение сети: для проверки из России компьютер должен находиться в российской сети. Запуск разовый, без автоматической отправки результата на GitHub; регулярное расписание на домашнем компьютере или VPS пока не настроено.
