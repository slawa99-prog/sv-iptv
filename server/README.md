# Российский узел проверки SV IPTV

Пакет для Ubuntu 24.04: проверяет каналы с сети VPS и хранит результаты независимо
от домашнего компьютера и зарубежного GitHub Actions. Основной `main/tv.m3u`
этот пакет не изменяет. Перед использованием российской сборки для приставок
нужно сравнить первый полный отчёт с домашним и проверить подозрительные кадры.

## Установка

На сервере достаточно 2 ядер и 4 ГБ памяти для начала проверки с двумя рабочими
процессами. Это стартовая настройка, а не измеренная гарантия времени полного прохода.
Панель ispmanager не требуется. Не устанавливайте этот пакет на чужой или
уже занятый другим проектом сервер без проверки путей.

Получите каталог `server` из этой версии репозитория и выполните:

```bash
sudo bash server/install.sh
```

Установщик устанавливает Python, Git и FFmpeg из репозиториев Ubuntu, создаёт
отдельного системного пользователя `sv-iptv-ru`, службу и таймер. Он не меняет
пароль, настройки SSH, firewall или действующие плейлисты.

Первый проход запускается сразу. Следующие — через 6 часов после завершения
предыдущего, без наложения; после перезагрузки — через примерно 5–7 минут.
Один проход ограничен шестью часами. Результаты и история сохраняются на диске;
совместимый недавний промежуточный результат может использоваться повторно.

```bash
sudo journalctl -u sv-iptv-ru.service -f
sudo systemctl status sv-iptv-ru.service
sudo systemctl list-timers sv-iptv-ru.timer
sudo systemctl start --no-block sv-iptv-ru.service
```

## Состав проверки

Каждый запуск получает актуальный `main` только из `slawa99-prog/sv-iptv`.
Применяется тот же фильтр разрешённых каналов, проверка видео, звука, продвижения
эфира и известных визуальных заглушек. История другого узла не импортируется.
Адреса с меткой ограничения по стране проверяются: узел находится в России.
Регион VPS сам по себе не доказывает доступность потока в домашней сети.

Рабочий каталог: `/var/lib/sv-iptv-ru/results`. В нём `status.json`, `history.json`,
`backups.json`, `tv.m3u`, `node.json`, промежуточные результаты и проблемные кадры.
`tv.m3u` здесь — результат VPS, а не основной плейлист на GitHub. Если защитные
пороги блокируют сборку, отчёт получает `publication: blocked`; M3U может остаться
от предыдущего успешного прохода. Дата M3U — `last_published_utc` в отчёте.

## Сохранение результатов в GitHub

Без отдельного ключа проверка работает, результаты остаются на сервере.
Для автоматической публикации нужен fine-grained GitHub token владельца:
только репозиторий `slawa99-prog/sv-iptv`, разрешение Contents: read and write.
Ключ вводится на сервере в `/etc/sv-iptv-ru/github-token`, владелец root, режим 0600.
Не добавляйте ключ в Git, командную строку, отчёт или переписку.
Служба получает его через systemd LoadCredential.

Код публикует только фиксированный набор файлов в отдельную ветку `ru-checks`
того же репозитория. История российского узла остаётся отдельной; основной
`main`, его плейлист и история не затрагиваются. При конфликте обновления
ветки принудительная запись запрещена, а локальный отчёт сохраняется.
Ограничение на ветку реализовано кодом; само разрешение Contents даёт доступ
к содержимому выбранного репозитория, а не только к этой ветке.

После настройки ключа публикация произойдёт в конце следующего полного прохода.
Неудачный доступ к GitHub не удаляет локальные результаты. Кадры и промежуточные
результаты остаются локально; публично сохраняются завершённые отчёты и M3U.

## Обновление и остановка

Проверяющий код и каталоги обновляются перед каждым проходом из `main`.
Чтобы обновить сам серверный запускатель/службу, повторите установку в момент,
когда проверка не выполняется. Ключ и накопленная история сохраняются.

```bash
sudo systemctl stop sv-iptv-ru.timer sv-iptv-ru.service
sudo systemctl disable sv-iptv-ru.timer
```

Остановка службы не прекращает аренду VPS у хостера.
